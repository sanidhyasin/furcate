Rewind an AI agent to any step.
Run it again.

Furcate records every step of an agent run and checkpoints its sandbox at each model call. When a run goes wrong, reopen it at any step, with the same files, processes and conversation, and run it again with a different prompt, model or tool output.

The demo is 807 real Claude runs, read-only. No sign-up.

A trace shows what happened. Not which step decided it.

Agents are random, so one failed run is one sample. Rerunning from the start mixes every decision together, and reading the trace only tells you the story after the fact.

Fork from the step, not from the start.

Restore any step into N sandboxes, resend the exact request with one change, and get a pass rate with a 95% interval. Compare steps and the drop shows you the decision that broke the run.

Keep the failure as a test.

A checkpoint of a real failure becomes an eval case: a portable bundle that any machine can restore. A GitHub Action runs it on every pull request that changes the prompt.

01 / How it works

Trace, checkpoint, fork.

  1. STEP 01

    Trace

    Every model call and tool call is an OpenTelemetry span. A collector with a write-ahead log stores the spans in ClickHouse, and each prompt, completion and tool output once, by hash.

    OTLP · ClickHouse · Postgres
  2. STEP 02

    Checkpoint

    At each model call the sandbox is snapshotted: a Firecracker VM with its memory and running processes, or a container's files. It's taken while the model is thinking, so the agent never waits for it.

    tine microVMs · Docker
  3. STEP 03

    Fork

    Restore step k into N sandboxes, offline, and resend the recorded request byte for byte with a change: an added instruction, another model, a different tool output. Changes only append, so the prompt cache stays warm.

    furcate fork -step 5 -n 20
  4. STEP 04

    Bisect and eval

    Binary search over steps by pass rate, with intervals, finds the decision that broke the run. Checkpoints of real failures become eval cases that run in CI.

    furcate bisect · furcate eval

04 / Works with

tine

Firecracker microVMs. Checkpoints keep memory and running processes; forks start in milliseconds, offline.

Docker

Runs on a laptop. Checkpoints keep the files; processes restart in forks.

Claude Code

Unmodified, through a recording proxy: fork from any of its API requests.

OpenTelemetry

Any OTLP SDK can send plain traces to the collector and browse them in the UI.

GitHub Actions

Eval cases on every pull request, with pass rates and their difference commented.

Claude models

Raw request bytes are kept and resent as they were, so thinking blocks and the prompt cache survive a fork.

05 / Install

One binary, a compose file, an API key.

  1. Install the binary for macOS or Linux (or go install github.com/sanidhyasin/furcate/cmd/furcate@latest).

    curl -fsSL "https://github.com/sanidhyasin/furcate/releases/latest/download/furcate_$(uname -s)_$(uname -m | sed s/aarch64/arm64/).tar.gz" | tar -xz furcate
sudo mv furcate /usr/local/bin/

  2. Start the stores, the collector and the web UI on 127.0.0.1:7070.

    git clone https://github.com/sanidhyasin/furcate && cd furcate
docker compose --profile app up -d --wait

  3. Run the example agent, then find the step where it went wrong.

    export ANTHROPIC_API_KEY=...
furcate run -task examples/csv-report/task.json
furcate bisect -n 10 -max-usd 5 <run-id>

Every release is checked by running these steps on a fresh machine as soon as it's published.
